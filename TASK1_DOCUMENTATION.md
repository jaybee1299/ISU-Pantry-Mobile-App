# Task 1 – ISU School Pantry Web App Data and AI Prototype

For Task 1, I prepared the data needed for the first version of the ISU School Pantry web application. The application is being built from the ground up, so there is not yet any real registration, volunteer, scheduling, or application-usage data. The only data currently available is a small FAQ/reference dataset that I created from verified public information about the School Street Food Pantry. The raw file contains 10 records and six fields: id, category, audience, question, answer, and source.

I completed preprocessing with a Python script. The script removes extra spaces, converts the category and audience values to lowercase, checks that each record contains a question, answer, and source, and removes duplicate questions. The raw dataset contains 10 records, and all 10 remain after cleaning. The cleaned file is stored in `data/pantry_faq_clean.csv`, where it can be used directly by the prototype.

For the AI portion, I am using a simple retrieval-augmented generation style workflow. ChromaDB was selected as the vector database because it can run locally and persist the vectors inside the project during development. Since the FAQ entries are short, each FAQ row is used as one chunk rather than splitting it into smaller pieces. The question and answer are combined into one retrieval document. Sentence Transformers with the `all-MiniLM-L6-v2` model converts each chunk into an embedding, and the embeddings are stored in the local `vector_db` folder.

The prototype is a web application rather than a mobile application. The frontend is a simple browser page with a question box and a few quick options such as eligibility, location, and volunteering. When the user submits a question, JavaScript sends it to the Flask backend. The backend converts the question into an embedding, searches ChromaDB for the most relevant FAQ entries, selects the best matching verified answer, and sends the response back to the browser. The page then displays the answer and its source.

This Task 1 prototype demonstrates the full flow from user input to backend retrieval and output while keeping the interface minimal. Future work will add actual pantry-user and volunteer registration, scheduling, a production database, authentication, and a more complete AI assistant. Any test records created before deployment will be clearly labeled as synthetic or test data.
